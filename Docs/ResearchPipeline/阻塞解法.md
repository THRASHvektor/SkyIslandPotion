# 项目阻塞解法 — 用 SoftUEBridge 自动化 AnimBP Slot 与 PSD_IceCombat

**生成时间**：2026-06-22
**结论**：两个红色阻塞点**都可以用项目自建的 SoftUEBridge 解开**，不需要手动操作 UE 编辑器。
**证据来源**：SoftUEBridge 插件源码 + Opus Flow 脚本 + ABP 拓扑实测记录

---

## 核心发现

### 阻塞 #1: FullBody_Combat Slot — ✅ 可自动化

**阻塞点回顾**：blocking-issues.md 说"C++ 代码无法替你创建 slot 节点"。这在纯 C++ 层面是对的，但 **SoftUEBridge 不是纯 C++——它是编辑器自动化桥接**。

**源码证据**（`AddGraphNodeTool.cpp`）：

1. **第 501 行**：`NewObject<UEdGraphNode>(Graph, NodeClass, NAME_None, RF_Transactional)` —— 通用的节点创建，接受**任何 `UEdGraphNode` 子类**
2. **第 22-27 行**：已经 include 了 Animation Graph 支持头文件（`AnimationGraph.h`、`AnimGraphNode_Root.h`、`AnimGraphNode_LinkedInputPose.h`、`AnimGraphNode_LinkedAnimLayer.h`）
3. **第 607-636 行**：已经为 `UAnimGraphNode_LinkedAnimLayer` 做了特殊处理——证明 AnimBP 节点创建路径已被验证过
4. **第 652-657 行**：`ApplyNodeProperties` 有对动画图节点的 inner "Node" struct 的特殊处理——能设置 `FAnimNode_Slot` 的 `SlotName` 属性
5. `ConnectGraphPinsTool.cpp` 第 17 行明确说："For AnimBlueprints, also supports blend_stack, state_machine, and other animation graphs."

**`UAnimGraphNode_Slot` 是 `UEdGraphNode` 子类**（继承链：`UAnimGraphNode_Slot` → `UAnimGraphNode_Base` → `UEdGraphNode`）。`AddGraphNodeTool::CreateBlueprintNode` 的类解析（第 469 行 `FBridgePropertySerializer::ResolveClass`）会找到它。

### 阻塞 #2: PSD_IceCombat — ✅ 可自动化（已有成功先例）

**源码证据**（`_flow08_create_pss_ice.py`）：

这个 Opus Flow 脚本**已经成功**用 Python 创建了 `PSS_Ice` schema 并配置了 `PSD_IceLocomotion`：
```python
# 复制默认 schema
created = unreal.EditorAssetLibrary.duplicate_asset(SOURCE_SCHEMA, TARGET_SCHEMA)
# 修改 channel weights
channel.set_editor_property("weight", TARGET_WEIGHT)
# 保存 schema
unreal.EditorAssetLibrary.save_loaded_asset(ice_schema)
# 把 schema 赋给 database
db.set_editor_property("schema", ice_schema)
unreal.EditorAssetLibrary.save_loaded_asset(db)
```

**`PSD_IceCombat` 用同样的模式**：复制 `PSD_IceLocomotion`（或 `PSD_Default`）→ 配置 schema → 添加战斗动画 → 保存。

**SoftUEBridge 的 `run-python-script` 工具**能执行这段 Python（在 UE 内嵌解释器里跑），不需要手动开编辑器。

## 解阻塞操作手册

> **前提**：UE 编辑器必须运行且 SoftUEBridge 插件已启用。所有命令通过 `soft-ue-cli` 执行。

### 第一步：探查当前 AnimGraph 拓扑（获取节点 GUID）

```bash
# 列出 AnimGraph 所有节点和连接
py -3 -m soft_ue_cli blueprint graph inspect \
  /Game/Blueprints/Character/Hero/ABP_SandboxCharacter \
  --callable-name AnimGraph --include-positions
```

从输出里找到：
- `DefaultSlot` 节点的 GUID（当前唯一的 slot）
- `SaveCachedPose` 节点的 GUID（缓存的运动基础姿态）
- `LayeredBoneBlend` 节点的 GUID（上半身分层混合）
- 每个节点的输入/输出 pin 名称

**这步是只读的，不会改任何东西。**

### 第二步：添加 FullBody_Combat Slot 节点

```bash
py -3 -m soft_ue_cli blueprint node add \
  /Game/Blueprints/Character/Hero/ABP_SandboxCharacter \
  AnimGraphNode_Slot \
  --graph-name AnimGraph \
  --properties '{"Node": {"SlotName": "FullBody_Combat", "Group": "DefaultGroup"}}'
```

- `node_class`: `AnimGraphNode_Slot` —— SoftUEBridge 的类解析会找到 `UAnimGraphNode_Slot`
- `properties.Node.SlotName`: 设置 slot 名为 `FullBody_Combat`
- `properties.Node.Group`: 设置组为 `DefaultGroup`（与现有 DefaultSlot 同组）
- `auto_position`: 默认 true，会自动放在不重叠的位置

**返回值**：新节点的 GUID——记下来，下一步要用。

### 第三步：把 FullBody_Combat 接入图

根据 wiring guide 的目标结构：

```
MM 结果 → SaveCachedPose("LocomotionBase") → FullBody_Combat → LayeredBoneBlend.BasePose
```

需要两步连接：

```bash
# 连接 1: SaveCachedPose 的输出 → FullBody_Combat 的输入
py -3 -m soft_ue_cli blueprint pin connect \
  /Game/Blueprints/Character/Hero/ABP_SandboxCharacter \
  <SaveCachedPose_GUID> <输出pin名> \
  <FullBody_Combat_GUID> <输入pin名>

# 连接 2: FullBody_Combat 的输出 → LayeredBoneBlend 的 BasePose
py -3 -m soft_ue_cli blueprint pin connect \
  /Game/Blueprints/Character/Hero/ABP_SandboxCharacter \
  <FullBody_Combat_GUID> <输出pin名> \
  <LayeredBoneBlend_GUID> <BasePose_pin名>
```

**注意**：pin 名称需要从第一步的拓扑探查结果里确认。AnimGraphNode_Slot 的输入 pin 通常叫 `InPose`，输出 pin 通常叫 `OutPose`。SaveCachedPose 的输出是 `Pose`。LayeredBoneBlend 的输入是 `BasePose` 和 `BlendPose`（对应 UpperBody slot）。

**重要**：wiring guide 的 Risk 1 说"一次只改一个图连接，每次改完 compile"。建议：

```bash
# 连接 1 后先编译验证
py -3 -m soft_ue_cli blueprint compile /Game/Blueprints/Character/Hero/ABP_SandboxCharacter

# 确认无误后再做连接 2
# 连接 2 后再编译
py -3 -m soft_ue_cli blueprint compile /Game/Blueprints/Character/Hero/ABP_SandboxCharacter
```

### 第四步：保存资产

```bash
py -3 -m soft_ue_cli asset save /Game/Blueprints/Character/Hero/ABP_SandboxCharacter
```

### 第五步：移除 C++ 临时映射

阻塞 #1 解开后，`SIPGameplayAbility_Attack.cpp:558` 的 `"FullBody_Combat" → "DefaultSlot"` 临时重映射可以移除。

```cpp
// 删掉这行（或恢复为正确的 slot 名）
Slot = FName("DefaultSlot");  // 临时映射，现在可以删了
```

改完后热重载：
```bash
py -3 -m soft_ue_cli trigger-live-coding
```

### 第六步：验证

```bash
# 启动 PIE
py -3 -m soft_ue_cli pie-session start --mode SelectedViewport

# 按攻击键
py -3 -m soft_ue_cli trigger-input key --key LeftMouseButton

# 查日志确认 slot 正确
py -3 -m soft_ue_cli get-logs --filter "CombatSemantic" --lines 20
py -3 -m soft_ue_cli get-logs --filter "AnimBridge" --lines 20

# 截图看效果
py -3 -m soft_ue_cli capture viewport --output combat_test_1

# 停止 PIE
py -3 -m soft_ue_cli pie-session stop
```

对照 wiring guide 的 Case A-D 验证清单。

## PSD_IceCombat 创建方案

### 方案 A：用 run-python-script（推荐，有 _flow08 先例）

写一个 Python 脚本 `_create_psd_ice_combat.py`（放在 `Scripts/` 下），复用 `_flow08_create_pss_ice.py` 的模式：

```python
import unreal

# 源资产：复制 PSD_IceLocomotion 作为基础（它已有 Ice schema）
SOURCE_DB = "/Game/Characters/UEFN_Mannequin/Animations/MotionMatchingData/Databases/PSD_IceLocomotion"
TARGET_DB = "/Game/Characters/UEFN_Mannequin/Animations/MotionMatchingData/Databases/PSD_IceCombat"

def main():
    # 1. 复制 IceLocomotion 数据库作为基础
    if not unreal.EditorAssetLibrary.does_asset_exist(TARGET_DB):
        created = unreal.EditorAssetLibrary.duplicate_asset(SOURCE_DB, TARGET_DB)
        if not created:
            raise RuntimeError(f"Failed to duplicate {SOURCE_DB} -> {TARGET_DB}")
    
    # 2. 加载新数据库
    db = unreal.EditorAssetLibrary.load_asset(TARGET_DB)
    if not db:
        raise RuntimeError(f"Failed to load {TARGET_DB}")
    
    # 3. TODO: 添加战斗动画到数据库
    #    这步需要知道要加哪些动画资产——从 MageRetarget 清单里找战斗动画
    #    具体API: db.add_animation(...) 或通过 schema 配置
    #    需要探查 PoseSearchDatabase 的 Editor API
    
    # 4. 保存
    unreal.EditorAssetLibrary.save_loaded_asset(db)
    print(f"PSD_IceCombat created at {TARGET_DB}")

if __name__ == "__main__":
    main()
```

通过 SoftUEBridge 执行：
```bash
py -3 -m soft_ue_cli run-python-script --file Scripts/_create_psd_ice_combat.py
```

### 方案 B：用 asset create + set-property

如果 `PoseSearchDatabase` 是 `UDataAsset` 子类（`CreateAssetTool.cpp` 第 246 行支持）：

```bash
# 创建空 PSD
py -3 -m soft_ue_cli asset create \
  /Game/Characters/UEFN_Mannequin/Animations/MotionMatchingData/Databases/PSD_IceCombat \
  --asset-class PoseSearchDatabase

# 设置 schema 属性为 PSS_Ice
py -3 -m soft_ue_cli asset set-property \
  /Game/Characters/UEFN_Mannequin/Animations/MotionMatchingData/Databases/PSD_IceCombat \
  --property schema --value /Game/Characters/UEFN_Mannequin/Animations/MotionMatchingData/Schemas/PSS_Ice
```

**注意**：方案 B 需要验证 `PoseSearchDatabase` 是否是 `UDataAsset` 子类。如果不是，用方案 A。

### 方案 B 的验证

```bash
# 查类层级确认
py -3 -m soft_ue_cli class-hierarchy --class PoseSearchDatabase
```

## 风险与注意事项

1. **AnimGraphNode_Slot 的 pin 名称**——我推断输入叫 `InPose`、输出叫 `OutPose`，但需要第一步的拓扑探查确认。如果 pin 名不同，连接命令要调整。

2. **图的连接顺序**——wiring guide Risk 1 强调"一次改一个连接，每次改完 compile"。不要一次性做所有连接。

3. **PSD_IceCombat 的动画内容**——创建空数据库只是第一步，还需要往里加战斗动画。这需要从 `MageRetarget_IceRuneDagger_Manifest.json` 里找战斗动画资产列表，然后用 Python API 加到数据库。这步可能需要探查 `UPoseSearchDatabase` 的编辑器 API。

4. **UE 5.4 的 PoseSearch 限制**——`anim pose-search *` CLI 命令不可用（需 5.5+），但 `run-python-script` 用的是 `unreal.EditorAssetLibrary` + `set_editor_property`，这是通用 Python API，不受 5.5 限制。`_flow08` 已证明在 5.4 上能工作。

5. **备份**——操作前先 git commit 当前状态，并用 `asset save` 保存当前 AnimBP。如果改坏了，可以从 git 恢复或用 `git checkout` 恢复 uasset 文件。

## 这意味着什么

**项目 2 个月的阻塞，可以用项目自建的工具解开。**

张力感悟里说的"你建了 SoftUEBridge，但你的阻塞点恰恰是'需要在 UE 编辑器手动操作'的事，而你没用自己建的桥接去解它"——这句话现在有了可执行的操作手册。

**建议执行顺序**：
1. 先做阻塞 #1（AnimBP Slot）——影响最大，操作最清晰
2. 验证战斗动画在正确 slot 播放
3. 再做阻塞 #2（PSD_IceCombat）——需要更多动画资产探查
4. 验证语义尾态不再 walk-in-place

**预计耗时**：阻塞 #1 约 1-2 小时（探查+操作+验证），阻塞 #2 约 2-4 小时（创建+配置动画+验证）。
