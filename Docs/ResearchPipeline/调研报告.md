## 二、调研方向（从项目张力推导）

基于《项目张力感悟》的 9 条张力，调研优先级如下：

### P0 — 可能直接解开项目阻塞

#### P0.1: AnimBP Slot 自动化创建（张力 2）

**问题**：项目卡在"需要在 AnimBP 添加 FullBody_Combat slot 节点"2 个月。blocking-issues.md 说"C++ 代码无法替你创建 slot 节点"——但你自建的 SoftUEBridge 有 `blueprint node add` + `pin connect` + `compile` 三个工具。

**待联网调研**：
- UE 社区有没有人用 Python Editor Scripting 自动化 AnimBP slot 创建？
- `K2Node_AnimSlot` 节点能否通过 `blueprint node add` 添加？（SoftUEBridge 用通用 K2Node 接口）
- Epic 官方的 Editor Scripting 文档对 AnimBP 图编辑覆盖到什么程度？

**已知线索**：
- SoftUEBridge 能力参考 (`Client/SIP/Docs/05_Tools_and_RAG/SoftUECLI_Bridge_Capability_Reference_2026-06-18.md`) 明确 `blueprint node add` 支持 `K2Node_CallFunction`，但 AnimSlot 是 `K2Node_AnimSlot`，需验证
- `anim state-machine *` 工具不可用（需 UE 5.5+），但 slot 节点不是 state machine 节点
- Opus Flow 系列已证明 SoftUEBridge 能自动化 PoseSearch Tag 集成、PSD 路由等编辑器操作

**预期收益**：如果验证 `blueprint node add` 能添加 AnimSlot 节点，阻塞 #1 可直接用 SoftUEBridge 解开，项目立即能动。

#### P0.2: PoseSearch Database 在 5.4 的自动化路径（张力 2+3）

**问题**：阻塞 #2 是创建 `PSD_IceCombat`。SoftUEBridge 的 `anim pose-search *` 不可用（需 UE 5.5+），`asset create` 能创建资产但不确定能否创建 PoseSearchDatabase 并配置 schema。

**待联网调研**：
- UE 5.4 有没有 Python API 能创建 PoseSearchDatabase 并配置 schema？
- 社区有没有人在 5.4 上用 Python scripting 绕过 PoseSearch 自动化限制？
- 升级到 5.5 的成本和收益？（PoseSearchSchemaTools 在 5.5 可用）

**已知线索**：
- `asset create` 工具能创建 BP/Material/DataTable，但 PoseSearchDatabase 是特殊资产类型
- UE 5.5 的 PoseSearchSchemaTools 专门解这个问题
- 项目当前锁在 5.4.4，升级有风险（SoftUEBridge 适配 5.4）

### P1 — 给金色路径之后找参考

#### P1.1: GAS 多武器系统扩展范式（张力 4）

**问题**：金色路径只覆盖 Ice+RuneDagger。武器系统是硬编码优先链，不是设计文档说的"武器模块是战斗锚点"。

**待联网调研**：
- UE 社区做 GAS 武器系统的人是怎么从"一种武器"扩展到"多武器切换"的？
- 有没有成熟的插件/范式？（如 AbilitySet 配置驱动 vs 硬编码）
- Lyra starter game 的武器系统是怎么组织的？

**已知线索**：
- 项目已有 `SIPAbilitySet.cpp`，说明走的是 Lyra 风格 AbilitySet 路线
- Ryan Laley 的 YouTube 频道有 GAS 教程集中（已加入 seeds.yaml）

#### P1.2: Motion Matching + GAS 实战经验（张力 1+5）

**问题**：项目的技术核心是 GAS + Motion Matching + 语义战斗，但社区实践现状未知。这是项目最激进的技术选型——中期报告甚至没提 Motion Matching。

**待联网调研**：
- 有多少 UE 项目在用 GASP Motion Matching？社区反馈如何？
- Motion Matching + GAS 同时使用时的常见冲突？（项目已遇到：MM 抑制 + 宽限期）
- 语义战斗（非状态机驱动）有没有同类项目？

**已知线索**：
- Alexander Paschall（Epic 在职）的 YouTube 频道有 Motion Matching / GASP 内容（已加入 seeds.yaml）
- GASP 是 Epic 官方示例项目，但社区使用率未知

## 五、用户回来后的下一步

### 立即（P1，约 2 天）

1. **装 SkillSpector + 扫 Agent-Reach**：
   ```bash
   pip install skillspector
   skillspector scan https://github.com/Panniantong/Agent-Reach --no-llm
   ```
   看风险分，≤20 或用户确认后继续。

2. **装 Agent-Reach**：
   ```bash
   pip install agent-reach
   agent-reach install --env=auto --safe
   agent-reach doctor
   ```

3. **验证 web-access CDP 在 Windows**：
   ```bash
   node ".claude/skills/web-access/scripts/check-deps.mjs"
   ```

4. **验证 faster-whisper CUDA**：
   ```python
   import ctranslate2
   print(ctranslate2.get_cuda_device_count())
   ```

### 然后（P2-P4，约 2 周）

5. **跑 ue-discovery**：
   ```bash
   py -3 ".claude/skills/ue-discovery/scripts/discover.py" --seeds ".claude/skills/ue-discovery/config/seeds.yaml" --out queue.json
   ```
   Review queue.json，确认要调研的条目。

6. **人工下载视频**（`download_required: true` 的条目）到 `raw/<slug>/video.mp4`

7. **跑 ue-ingest**：
   ```bash
   py -3 ".claude/skills/ue-ingest/scripts/ingest.py" --queue queue.json --wiki ".obsidian/wiki"
   ```

8. **实际调研 P0 主题**（AnimBP slot 自动化、PoseSearch 5.4 路径）——用 Agent-Reach + web-access 联网，重点查 Reddit r/UnrealEngine、Epic 官方文档、YouTube 教程

9. **产出 LaTeX 调研笔记**（ai-notes 管线）
